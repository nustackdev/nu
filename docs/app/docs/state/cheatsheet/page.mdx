# State Cheatsheet

Think of Loomi's state as a mix between a nested Python dictionary and a mini-database. 
It's a hierarchical tree where every node can be a dictionary, list, or primitive value.
You can traverse, modify, and observe this tree with a clean and intuitive API.

## 🧠 The Mental Model

Loomi's state management works like a tree:

```
state
├── users
│   ├── user1
│   │   ├── name: "Alice"
│   │   └── settings: {theme: "dark"}
│   └── user2
│       └── name: "Bob"
└── tasks
    ├── high_priority: {...}
    └── low_priority: {...}
```

You navigate this tree with path components like `state.dict("users", "user1")` to access the `user1` node.

## 🧩 Key Concepts

- **Path Navigation**: Access nested data with dot notation or path components
- **Dictionary & List Nodes**: State nodes are either dict-like, list-like, or primitive values
- **Transactions**: Atomic operations across multiple state changes
- **Observers**: Subscribe to changes at specific paths
- **Synchronous & Asynchronous**: Both APIs available (choose what fits your app)

## 🔄 Node Operations

Node operations work on any tree node (dictionary or list) and provide powerful manipulation capabilities. All node operations can be applied at both the current node level or at nested paths.

### Node Operation Patterns

| Pattern | Sync Example | Async Example | Description |
|---------|-------------|---------------|-------------|
| Root operation | `node.operation()` | `await node.operation()` | Operates on the current node |
| Path operation | `node.operation("path", "to", "nested")` | `await node.operation("path", "to", "nested")` | Operates on a nested node |
| Root with transaction | `node.operation(txn=txn)` | `await node.operation(txn=txn)` | Operates on root with transaction |
| Path with transaction | `node.operation("path", "to", "nested", txn=txn)` | `await node.operation("path", "to", "nested", txn=txn)` | Operates on path with transaction |

### Transactions and Node Operations

**Creating nodes within a transaction**:
   ```python
   # Sync
   with state.transaction() as txn:
       dict_node = state.dict("users", txn=txn)  # Node created within transaction
       dict_node.set("alice", value={"active": True})  # Automatically uses transaction
   
   # Async
   async with await state.transaction() as txn:
       dict_node = await state.dict("users", txn=txn)
       await dict_node.set("alice", value={"active": True})
   ```

When a node is created with a transaction, all operations on that node will automatically use that transaction unless explicitly overridden.

### Node Transformation Methods

The transformation methods (`transform`, `filter`,) provide powerful ways to manipulate node data:

- **Transform**: Applies function to each element while preserving structure
  ```python
  # Transform each item in a list
  node.transform(lambda x: x.upper())
  
  # Transform each value in a dictionary (keys remain the same)
  node.transform(lambda x: x * 2)
  ```

- **Filter**: Removes elements from a collection based on a predicate
  ```python 
  # Dictionary: filter_func takes (key, value)
  node.filter(lambda k, v: v["active"] == True)
  
  # List: filter_func takes (value)
  node.filter(lambda x: x > 10)
  ```

### Key Differences from Python Dictionaries/Lists

- All modifications are persistent and immediately visible to other clients
- Operations like `move_to` and `copy_to` are atomic
- Transactions ensure consistency across multiple operations
- Paths can navigate to deeply nested structures in a single call

## 💡 Pro Tips

1. **Chain operations** for cleaner code:
   ```python 
   # Instead of:
   settings = state.dict("users", "user1").get("settings")
   theme = settings.get("theme")
   
   # Do this:
   theme = state.dict("users", "user1", "settings").get("theme")
   ```

2. **Use transactions** for complex state updates to avoid race conditions:
   ```python
   with state.transaction() as txn:
       balance = state.dict("accounts", "alice", txn=txn).get("balance")
       state.dict("accounts", "alice", txn=txn).set("balance", value=balance - 100)
       state.dict("accounts", "bob", txn=txn).set("balance", value=bob_balance + 100)
   ```

3. **Pattern: Check-then-operate**
   ```python
   if state.exists("users", "alice"):
       user = state.dict("users", "alice")
       # Safe to operate on user
   ```

4. **Watch selectively** - Use appropriate depth for observers:
   - `depth=0`: Exact path only
   - `depth=1`: Direct children only
   - `depth=-1`: All descendants (use cautiously!)
